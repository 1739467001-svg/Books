## 1.1 引子：给自己请一个"不下班"的帮手

设想一下：你身边有这么一位帮手——

- 你在钉钉上发一句"把今天的群消息汇总成纪要"，它几分钟就办好；
- 你出差在外，发一句"把上周的报表拉出来算个环比"，它直接给你结果；
- 它**不下班、不喊累、24 小时在线**，工作上的杂活、生活里的琐事，交给它就行。

这不是科幻。本书要带你亲手"养"出这样一位帮手——它叫 **OpenClaw**，江湖人称"**小龙虾**"。

而且我们不满足于"装个工具玩玩"。我们的终极目标，是把它一步步**稳定化、专精化，封装成一名真正的"数字员工"**：当它熟悉了你某一块业务、某一个领域，它就不再只是个助手，而是能独当一面替你干活的"同事"（这是第 3 章的主题）。

要走到那一步，得先从"认识它、养活它"开始。

> **提示**：本书的技术路线很明确——**全程依托阿里云生态**：用阿里云的服务器当它的"身体"，用阿里云的大模型 tokens 当它的"饲料"，并让它在**钉钉**里和你朝夕相处。为什么这么选？1.4 节会讲清楚。

## 1.2 小龙虾是什么

### 一句话定义

> **OpenClaw 是一款开源、免费、可以部署在你自己服务器上的"自主型"AI 助手（AI Agent）。**

它和你熟悉的聊天机器人最大的不同，在于一个词：**会动手**。

### 为什么叫"小龙虾"

OpenClaw 里的 **Claw** 是"钳子、爪子"。带着一对大钳子、又接地气的形象，可不就是小龙虾嘛。于是中文社区亲切地叫它"**小龙虾**"，把部署、运维、调教它的过程戏称为"**养龙虾**"。本书"小龙虾"与"OpenClaw"通用，指的都是它。

> **注意（它的曾用名）**：这个项目改过名——最早叫 **Warelay**，后来因商标问题先改为 **Moltbot**，很快又定名 **OpenClaw**。你在网上看到旧名字，把它当"小龙虾的曾用名"即可，但**命令、下载地址一律以现在的官方文档为准**。

### "动嘴" vs "动手"

| | 普通聊天机器人 | 小龙虾（OpenClaw） |
|---|---|---|
| 本质 | 会"动嘴"的顾问 | 会"动手"的助手 |
| 你说"帮我汇总这周报表" | 给你一段思路 / 文案 | 直接去拉数据、算好、给结果 |
| 能不能操作系统、文件、软件 | 不能 | 能（在你授权范围内） |
| 任务有很多步 | 你得一步步喂 | 它自己拆步骤、连着做完 |
| 跑在哪 | 别人的云 | **你自己的服务器**（本书放阿里云） |

一句话：**普通机器人告诉你"该怎么做"，小龙虾直接帮你"把它做了"。**

正因为它真能动手、还要 24 小时在线替你干活，所以我们才要给它一个稳定的"身体"和"住所"——这就引出了本书的养虾框架。

## 1.4 怎么"养"一只小龙虾：身体 · 饲料 · 池水（全书框架）

这是本书最重要的一张"思维地图"，请记牢。养一只真龙虾，你得操心三件事：它住在哪、吃什么、在什么水里游。养小龙虾（OpenClaw）一模一样：

| 三部分 | 真龙虾 | 小龙虾（OpenClaw） | 我们的选择 |
|---|---|---|---|
| 🦞 **身体** | 虾的躯体、住的窝 | 它运行的那台机器 | **阿里云轻量应用服务器** |
| 🦞 **饲料** | 喂它的食物 | 它"思考"消耗的 tokens | **阿里云大模型服务 · 入门版** |
| 🦞 **池水** | 它生活的水域 | 你和它打交道的聊天环境 | 企业微信 / QQ / 飞书 / **钉钉**（本书围绕钉钉） |

【配图：三部分养虾法示意图——一只龙虾，标注"身体=阿里云服务器""饲料=tokens""池水=钉钉等聊天环境"】

把这三样配齐，一只能干活的小龙虾就"养成"了。本章 1.5、1.6、1.7 三节，就是分别把"身体、饲料、池水"一一备齐。

### 为什么整套都选阿里云生态 + 钉钉？

- **要 24 小时在岗**：数字员工不能你一关电脑就罢工。放在**云服务器**上，它才能不眠不休——这是"身体"必须上云的根本原因。
- **要稳定供"粮"**：tokens 是它的口粮，用**阿里云的大模型服务**，和服务器同处一个生态，开通、计费、调用都顺手。
- **要扎根你真实的工作场景**：很多团队（包括本书参照的老师）日常就泡在**钉钉**里办公。让小龙虾住进钉钉，它才能真正融入你的工作流，而不是另开一个孤岛。
- **生态合一，省心**：服务器、大模型、（以及与钉钉的打通）都在阿里系，少踩跨平台的坑。

> **注意**：池水那一格列了四种环境（企业微信、QQ、飞书、钉钉），它们都可作为小龙虾的"聊天入口"。**本书统一围绕钉钉来讲**；你若用其它三种，思路相通，但具体接入步骤请以对应平台官方文档为准。

> **提示**：记住这三个字——**身体、饲料、池水**。本书后面所有"养虾、喂虾、调教虾"的动作，都能对应回这三部分。框架清楚了，再多的步骤都不会乱。

## 1.5 龙虾的身体：阿里云轻量应用服务器

先给小龙虾一副"身体"——一台 24 小时不关机的云服务器。

### 为什么用云服务器（而不是自己电脑）

- **不间断**：数字员工要 7×24 在岗，自己电脑总要关机、休眠、带出门。
- **稳定可达**：固定的公网地址，方便和钉钉等平台对接。
- **省心**：阿里云负责机房、网络、电力，你只管养虾。

本书选**阿里云轻量应用服务器**——它面向个人和入门用户，开通简单、价格友好，正适合养第一只龙虾。

### 第一步：开通一台轻量应用服务器

到阿里云控制台开通（**步骤与界面以阿里云官方最新文档为准**），开通时主要关注：

- **地域**：选离你 / 你的用户近的地域。
- **配置**：入门可从 `<较小规格，如 2 核 2G/4G 起；以你的负载和官方建议为准>` 起步，不够再升级。
- **操作系统**：选一个主流 Linux 发行版 `<以官方与你的熟悉度为准>`。
- **网络**：记下分配给你的**公网 IP**，后面要用。

【配图：阿里云轻量应用服务器开通页关键选项截图（地域 / 配置 / 系统 / 公网 IP）】

> **提示**：第一次养虾别贪大配置。**先用入门规格跑通整条链路**，确认能用了，再按需要升配。省下来的钱可以多买点"饲料"（tokens）。

### 第二步：连上服务器

开通后，按官方指引连接到这台服务器（控制台网页终端，或本地用 SSH，**方式以官方为准**）。连上后，你就站在了"龙虾的身体"内部，可以往里装东西了。

> **避坑（安全第一课）**：服务器一开通就暴露在公网。请第一时间：① 用**强密码 / 密钥**登录；② 通过阿里云**安全组 / 防火墙只开必要端口**，别全开；③ 别用最高权限到处裸跑。安全细节本系列会持续强调（这正是把它做成可靠数字员工的前提）。

### 第三步：在服务器里部署小龙虾本体

身体有了，接下来把小龙虾装进去。和在自己电脑上装类似，OpenClaw 提供一键脚本等方式（**命令以官方最新文档为准**，下面是**示例结构**，请勿照抄占位符）：

```bash
# 在你的阿里云服务器上运行（示例结构，实际命令以 OpenClaw 官方文档为准）
<官方提供的一键安装命令>
```

脚本通常会自动准备运行环境（如 Node.js 等）、配置国内镜像加速、下载并安装小龙虾本体。跑完后，"龙虾的身体"就算搭好了。

> **注意**：装的过程不必纠结每行输出，能进行到下一步即可。验证"身体是否搭好"的统一标准，是后面 1.8 节能不能成功跑通第一个任务。

至此，**🦞 身体 ✅**。但现在它还只是个"没吃饭、没接触外界"的躯壳——接着喂饲料、放池水。

## 1.6 龙虾的饲料：tokens（阿里云入门版）

### 为什么 tokens 是"饲料"

小龙虾自己不会"思考"，思考这件事外包给一个**大模型**（它的"大脑"）。而每一次思考，都要消耗**tokens**（可粗略理解为"字数"）。

所以 tokens 就是喂给龙虾大脑的**口粮**：

> **没有饲料（tokens），龙虾再壮的身体也只是个躺平的壳，动不起来。**

### 我们的选择：阿里云大模型服务 · 入门版

为了和"身体"同处一个生态，本书的饲料也选**阿里云的大模型服务**（如通义千问 / 百炼等，**具体服务与套餐名以阿里云官方为准**），并开通**入门版 plan**——额度够养第一只龙虾练手，花费可控。

### 第一步：开通服务、拿到 API Key

到阿里云对应的大模型服务控制台，开通入门版，创建一个 **API Key**（一长串字符，是"取饲料的凭证"）。**步骤以官方最新文档为准。**

> **注意（钥匙红线）**：API Key 等于你账户的取款密码。
> - 不截图发群、不贴公开网页、**不提交到公开仓库**；
> - 不硬编码进脚本，建议放**环境变量**里；
> - 怀疑泄露立刻在控制台**吊销并重置**。

### 第二步：把饲料喂给龙虾

在小龙虾的配置里，填入"用哪家大脑、用哪个 API Key"。**示例结构**（仅示意，真实字段以官方为准）：

```json
{
  "provider": "<阿里云对应的大模型服务标识>",
  "apiKey": "<你的 API Key（建议用环境变量注入，勿明文硬编码）>",
  "model": "<选用的模型名，以官方文档为准>"
}
```

填好后，龙虾的"身体"就接上了"会思考的大脑"。

### 省着喂：别让饲料白白浪费

tokens 花钱，几招帮你"喂得省":

- **任务说清楚**：一次讲明白，少来回返工。
- **挑性价比模型**：日常杂活用便宜的小模型，复杂任务再上强的。
- **设用量上限**：在阿里云控制台设额度封顶，避免"龙虾很能吃、账单很吓人"。
- **关掉空转**：别设一堆用不上的高频自动任务白白烧 token（自动化在第 2、3 章细讲）。

> **提示**：入门阶段，先用**最便宜的喂法**把流程跑顺。等它真成了帮你干活的数字员工，再按产出价值决定"加餐"。

至此，**🦞 饲料 ✅**。龙虾能动、能想了，但还没地方和你见面——该放池水了。

## 1.7 龙虾的池水：四种环境，围绕钉钉

### 池水是什么

"池水"就是小龙虾**生活、并和你打交道的环境**——也就是你给它下指令、看它干活、收它汇报的**聊天入口**。

你总不想每次都登录服务器、对着黑乎乎的终端敲命令吧？把它放进你天天用的聊天软件里，**像和同事发消息一样指挥它**，才是数字员工该有的样子。

### 四种可选池水

小龙虾能接入多种聊天环境，常见四种：

| 池水（聊天环境） | 适合 |
|---|---|
| 企业微信 | 用企业微信办公的团队 |
| QQ | 习惯 QQ 的个人 / 社群 |
| 飞书 | 用飞书的团队 |
| **钉钉** | **用钉钉办公的个人与团队（本书主线）** |

### 为什么本书围绕钉钉

本书参照的老师，日常**依托钉钉生态**办公——开会、审批、群协作、工作通知，全在钉钉里。让小龙虾住进钉钉这片"池水"，它就能**直接接住真实的工作流**：你在哪办公，它就在哪待命。

再加上前面"身体"(阿里云服务器) 和"饲料"(阿里云大模型) 都在阿里系，**阿里云 + 钉钉**这套组合一气呵成，养出来的龙虾扎根在你真实的工作土壤里，而不是飘在一个用完就忘的小窗口里。

### 把龙虾放进钉钉（接入流程概览）

接入钉钉的大致思路如下（**具体步骤、凭证字段、配置项均以钉钉开放平台与 OpenClaw 官方文档为准**，下面只给框架）：

1. **在钉钉侧创建一个"机器人 / 内部应用"**：在钉钉开放平台为你的组织创建一个机器人或企业内部应用，作为小龙虾在钉钉里的"化身"。
2. **拿到对接凭证**：获取对接所需的凭证（如 `<AppKey / AppSecret / 机器人 Webhook / 加签密钥 等，以官方为准>`）。
3. **在小龙虾里配置钉钉入口**：把上述凭证填入小龙虾的消息接入配置（字段名以官方为准），让它能收发钉钉消息。
4. **绑定与权限**：完成"仅限你 / 你的组织可用"的绑定与必要权限设置，别让无关的人也能指挥它。

【配图：钉钉里与小龙虾机器人的第一段对话——你发"在吗"，它回"在，请下达任务"的截图】

> **避坑**：钉钉对接涉及的各种密钥（AppSecret、加签密钥等）和 API Key 一样是钥匙，按 1.6 的红线保管，**别外泄、别硬编码、可随时吊销**。

> **注意**：务必做好"谁能指挥它"的权限边界。小龙虾是会动手的，**池水里能对它喊话的人，就是能调动它干活的人**——这扇门要看好。

至此，**🦞 池水 ✅**。身体、饲料、池水三样齐活，养虾的硬件部分就完成了。

## 1.9 本章小结 + 下章预告

这一章，你完成了从"认识"到"养成"的第一步：

- **认识**了小龙虾——一只开源、会动手、要 24 小时在岗的自主 AI 助手，以及我们把它做成"数字员工"的终极目标；
- 看清了它在**工作与生活**两条线上能帮的忙；
- 最重要的是，掌握了贯穿全书的**"身体 · 饲料 · 池水"三部分养虾法**，并亲手用**阿里云轻量服务器（身体）+ 阿里云入门版 tokens（饲料）+ 钉钉（池水）**这套阿里云生态，把第一只龙虾养了出来。

但"养活"只是起点。一只刚会打招呼的龙虾，离"替你独当一面"还差得远。

> **下一章预告**：第 2 章《带龙虾去实战：养好之后，让它去闯世界》。养活只是第一步，接下来该带它**历练**了——我们会带它去上学、打工、炒股、种田、高考、逛社区，在真实世界的试炼场里看清它的强项，为第 3 章"转正"成数字员工做准备。
