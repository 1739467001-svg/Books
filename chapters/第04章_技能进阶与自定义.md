## 4.1 开篇：从"够用"到"称手"——以及给你的难度导航

前三章，你已经能让小龙虾装好、用好、放养。它现在装的，大多是**通用技能**——浏览器、文件、邮件、抓取……对付日常足够了。

但你的工作是**独一无二**的：你们公司有内部系统、你有自己的私有数据、你有一套别人没有的固定流程。通用技能像一把"够用的瑞士军刀"，而这一章，要教你给龙虾配上**只属于你的专用工具**，让它从"够用"变成"称手"。

> **难度导航（请先读这段）**：这是全书**最进阶**的一章，但不是每一节都难。
> - **4.2–4.4 节**：概念 + 逛市场 + 不写代码的轻量定制，**人人都能用**。
> - **4.5–4.7 节**：开始碰**一点点代码和配置**，主要面向愿意折腾、或身边有技术同事的读者。看不懂完全没关系——**可以直接跳到 4.8**，等将来真有需要时再回来。

> **提示**：哪怕你永远不写代码，读完 4.2–4.4 也能让你的龙虾比别人好用一截。先把这部分吃透，进阶部分随缘。

## 4.2 再认识"技能"：它到底是什么、从哪来

### 技能 = 龙虾的"专长插件"

第 2 章我们打过比方：技能（Skill）是龙虾的一项项"专长"。再说得具体点——**技能就是给龙虾大脑配的一件件"工具"**。大脑负责"想"，技能负责"做"。没有"发邮件技能"，它再聪明也发不出邮件。

### 技能的三种来源

| 来源 | 说明 | 适合 |
|---|---|---|
| **官方内置** | 随龙虾自带的基础技能（第 1 章装的四件套等） | 所有人，开箱即用 |
| **技能市场 / 社区** | 别人写好、分享出来的技能 | 想扩展又不想自己写的人 |
| **自己写** | 你按官方开发文档定制的专用技能 | 要接私有系统、市场上找不到的需求 |

本章就沿着这三条线，由易到难走一遍。

### 一个技能通常长什么样（概念层）

你不用先懂代码，但理解一个技能"由哪几块拼成"，对后面很有用。一个技能通常包含三部分：

1. **说明书**：告诉龙虾大脑"这个技能能干嘛、什么时候该用我"。
2. **入口参数**：用的时候需要哪些信息（比如"发邮件"需要收件人、主题、正文）。
3. **执行逻辑**：真正干活的那段动作（比如真的去调用邮件服务）。

【配图：一个技能的"三件套"示意图——说明书 / 入口参数 / 执行逻辑，旁边画龙虾大脑指着说明书"决定要不要用它"】

> **提示**：记住"**说明书**"这块，它在 4.5 节会变成关键——**说明书写得好不好，直接决定龙虾会不会、以及会不会用对这个技能。**

## 4.3 把技能市场用透（无需写代码）

扩展龙虾最轻松的方式，就是去**技能市场 / 技能列表**里"逛街"。全程点鼠标，不碰代码。

### 逛市场的正确姿势

在操作界面里打开技能市场（路径以官方界面为准），看一个技能时，重点看四样：

- **它能干嘛**：描述是否正好对上你的需求。
- **它要什么权限**：是只读，还是能改文件、能联网、能发消息？
- **它的来源**：是官方 / 知名作者，还是来路不明？
- **更新与口碑**：是否还在维护、有没有人用过反馈。

【配图：技能市场界面截图，标注"描述 / 权限 / 来源 / 更新"四个查看重点】

### 技能的生命周期：装、配、用、更、停

一个技能从进门到退休，通常经历：

1. **安装**：点"安装"。
2. **授权 / 配置**：按提示给必要权限、填必要信息（如某服务的地址）。
3. **启用**：开启后龙虾才会在合适时候调用它。
4. **更新**：作者发新版时按需更新。
5. **停用 / 卸载**：不用了就关掉或删掉——**这也是一种安全操作**。

> **避坑**：装技能不是越多越好。**每多一个技能，就多一份权限、多一个潜在风险面。** 用不到的就停用或卸载，保持龙虾"清爽又安全"。

### 让技能"组队"干活

单个技能是工具，多个技能配合才是战斗力。比如第 2 章案例 7 的"下班收尾"，其实就是"日历 + 邮件 + 文件"几个技能在大脑指挥下组队完成的。你装的技能越互补，龙虾能串起来的工作流就越长。

### 选技能的"安全眼光"（承接 2.8 / 3.6）

> **注意**：技能是别人写的代码，跑在**你的电脑、用你的权限**。装一个来路不明、却要"完全控制电脑 + 联网"的技能，风险极高。**只从可信来源装技能，优先选权限最小、够用就好的那个。** 这条和第 2、3 章的安全原则一脉相承。

## 4.4 给龙虾"调教"：不写代码也能做的轻量定制

市场里的技能是"通用款"，但你可以不写一行代码，就把它"调教"得很贴合自己。靠三样东西：**配置项、人设/提示、记忆。**

### ① 用配置项贴合你

很多技能自带配置。例如：

- 给"邮件技能"设一个**默认签名**和默认语气；
- 给"抓取技能"设几个**默认来源网站**；
- 给"文件技能"设一个**默认归档目录**。

配好之后，你下指令就能更短——很多默认值它已经知道了。

### ② 用"人设 / 系统提示"定调

你可以给龙虾设定一段"工作风格说明"（人设 / 系统提示，入口以官方为准），比如：

> 「你是我的工作助理。回复一律用简洁中文；涉及发送、删除、付款的操作，一律先列清单等我确认；不确定的就先问我，别擅自发挥。」

这段话会持续影响它**所有**任务的风格和边界——相当于一次设定、长期生效。

### ③ 用记忆固化你的习惯（呼应 2.3.3）

结合记忆技能，把常用流程**取个名字**，变成"快捷语"：

> 「记住：我说'周报'＝把本周 `<项目>` 的进展汇总成模板格式，发给 `<某人>`，发送前给我确认。」

之后你只说"做周报"，一整套就跑起来了。

> **提示**：4.4 这三招，是"投入产出比最高"的定制——几分钟设置，天天受益，且零代码、零风险。**强烈建议每个读者都做一遍。**

## 4.5 写你的第一个自定义技能（进阶，开始碰一点代码）

> **从这里开始会出现代码。** 看不懂可以跳到 4.8；想试的读者，请**全程对照官方开发文档**操作，本节所有代码都是**示例结构 / 伪代码**，仅帮你建立画面感，**真实写法以官方为准**。

### 什么时候才需要自己写

绝大多数需求，市场里都有现成技能。只有两种情况才值得自己动手：

1. **市场上没有**你要的功能；
2. 你要接的是**只有你才有**的东西（公司内部系统、私有 API、专属流程）——这正是 4.6 节的主题。

### 一个自定义技能的骨架

回忆 4.2 的"三件套"：说明书、入口参数、执行逻辑。自己写技能，就是把这三块填出来。**示例结构**（仅示意，字段名与格式以官方开发文档为准）：

```json
{
  "name": "<技能名，如 查询天气>",
  "description": "<给龙虾大脑看的说明书：这个技能能做什么、什么时候应该用它>",
  "permissions": ["<这个技能需要的权限，如 network>"],
  "parameters": {
    "<参数名，如 city>": "<参数说明，如 要查询的城市>"
  }
}
```

执行逻辑部分（**伪代码**，真实语言与 API 以官方为准）：

```text
当龙虾决定调用这个技能时：
1. 读取它传来的参数（如 city）
2. 执行真正的动作（如调用一个天气接口）
3. 把结果整理成「人话」，返回给龙虾大脑
4. 大脑再把结果讲给你听
```

### 最关键的一步：把"说明书"写好

新手最容易忽视、却最重要的，是那段 `description`（说明书）。

龙虾的大脑**靠这段说明来判断"什么时候用这个技能、怎么用"**。说明书含糊，它就用错或不用；说明书清楚，它才会在对的时候、用对的参数调用。

| 反例（含糊） | 正例（清楚） |
|---|---|
| "天气工具" | "查询指定城市未来天气。当用户问某地天气、要不要带伞、适不适合出行时使用。参数 city 为城市名。" |

> **提示**：把 `description` 当成**写给一位新同事的"工具使用说明"**——他没见过这个工具，全靠你这段话判断何时该拿起它。你写得越具体（能干嘛、何时用、参数啥意思），龙虾用得越准。

### 小步测试，别一步登天

写好后，**先在本地用最简单的输入测一次**，确认它能被正确调用、能返回结果，再逐步加复杂度。别一上来就接到自动任务里——万一有 bug，自动跑反而放大问题。

## 4.6 接入你的私有系统 / API（进阶，最有价值的一节）

这是自定义技能最有价值的用途：**把龙虾接到只有你 / 你公司才有的系统上**——内部订单系统、私有数据库、公司内网 API、某个你在用的第三方 SaaS……接通之后，龙虾就能用大白话帮你查它、用它。

### 通用四步法

不管接什么系统，套路都一样：

1. **拿接口说明**：找到目标系统的 API 文档，搞清"调哪个地址、要传什么、返回什么"。
2. **配好认证**：大多数 API 需要身份凭证（API Key / Token / OAuth）。**安全地**配置它（见下）。
3. **封装成技能**：按 4.5 的骨架，把"调用这个 API"包成一个技能，写清说明书。
4. **让龙虾调用**：在合适的指令下，龙虾就会用这个技能去查 / 改你的系统。

【配图：数据流示意——你（聊天工具）→ 龙虾大脑 → 自定义技能 → 私有 API / 内部系统 →（返回）→ 整理成人话 → 你】

### 认证与密钥：第 1 章红线在这里尤其要命

接私有系统几乎一定要用到密钥 / 令牌。请把第 1 章 1.8 的红线再焊死一遍：

```bash
# 正确做法（示意）：把密钥放进环境变量或专门的密钥管理，别写死在代码里
export MY_SERVICE_TOKEN="<你的令牌>"
```

> **注意（安全红线）**：
> - **绝不**把 API Key / Token **硬编码**进技能代码，更别把含密钥的代码提交到公开仓库。
> - 用**环境变量**或官方推荐的**密钥管理**方式存放凭证。
> - 给凭证用**最小权限**：能只读就别给可写，能限定范围就别开全权。
> - 定期**轮换**，怀疑泄露立刻吊销。

### 让返回结果"说人话"

私有 API 返回的往往是一堆原始数据（一长串字段）。技能的价值之一，就是**让龙虾把它翻译成人话**。比如查订单系统，原始返回可能是几十个字段，但你要的只是一句："订单 `<号>` 已发货，预计明天到。"在技能的执行逻辑里做好这层整理，体验会好很多。

### 别忘了"不顺利"的情况

真实系统会超时、会报错、会限流。一个靠谱的技能要有基本的"抗造"意识：

- **限流**：别让龙虾高频猛打你的接口（尤其在自动任务里）。
- **错误处理**：接口报错时，让技能**如实告诉龙虾"失败了、为什么"**，而不是装作成功。
- **重试**：偶发失败可适度重试，但要有上限，别死循环。

### 场景示例：把"内部订单查询"做成技能

把上面串起来感受一下（**结构示意**，细节以你公司 API 和官方开发文档为准）：

- **说明书**：「查询内部订单状态。当用户问某订单到哪了、发货没、什么时候到时使用。参数 orderId 为订单号。」
- **认证**：用环境变量里的 `<内部系统 Token>`。
- **执行逻辑**：调用 `<内部订单 API>` → 拿到原始数据 → 整理成"状态 + 预计到达"一句话 → 返回。
- **用起来**：你在微信问"`<订单号>` 到哪了？"，龙虾调用这个技能，回你一句人话。

> **提示**：这一节虽然进阶，却是龙虾从"通用助手"变成"你公司专属助手"的分水岭。哪怕你自己不写，**把这个思路讲给你的技术同事，他也能照着帮你接。**

## 4.7 让自定义技能既可靠又安全

自己写的技能跑在你的权限上、还可能连着公司系统，所以"可靠"和"安全"必须一起抓。给你一份落地清单：

### 可靠性

- **划清权限边界**：技能只申请它真正需要的权限（只读就别要可写；只连指定域名/系统，别开"任意联网"）。
- **失败可观测**：把关键步骤和错误**写进日志**（位置以官方为准），出问题能查到原因。
- **版本与共享**：多人/团队共用时，给技能做版本管理，改动有记录、可回滚。

### 安全（再次敲黑板）

- **密钥安全**：见 4.6，环境变量 / 密钥管理 + 最小权限 + 定期轮换。
- **提示注入再警示**：如果你的技能会**处理外部数据**（网页、邮件、用户上传内容），要警惕里面藏的恶意指令。**别让技能拿着外部内容就无脑去执行危险动作**（删除、发送、调写接口）——承接 2.8 的核心忠告。
- **危险动作留确认**：技能若能"改 / 删 / 发 / 付"，默认走"先确认"，尤其在自动任务里。

> **避坑（一句话总则）**：**给技能的权限，按"它完成任务的最小必要"来给；给不准的时候，宁可少给。** 少给顶多多问你一次，多给可能闯一次祸。

## 4.8 本章小结 + 实操练习

这一章，你学会了给龙虾"加 buff"，让它从通用助手长成你的专属助理：

- 看懂了**技能的本质与三种来源**，以及"三件套"结构；
- 学会了**把技能市场用透**（逛、装、配、更、停）和**零代码轻量定制**（配置 / 人设 / 记忆）；
- （进阶）了解了**自己写技能的骨架**，尤其是"说明书决定龙虾会不会用对"；
- （进阶）掌握了**接私有系统 / API 的四步法**，以及贯穿始终的**密钥与安全**红线。

至此，龙虾的能力上限，基本由你的想象力（和安全意识）决定了。

### 留给你的实操练习

1. **（人人）** 去技能市场装一个新技能，安装时特别留意它要的**权限**，并按最小够用原则配置；用完若不需要就停用。
2. **（人人）** 用 4.4 三招做一次零代码定制：设一段"工作风格人设"，再把一个常用流程用记忆**取名成快捷语**（如"周报"）。
3. **（人人）** 检查你已装的技能，把**用不到的停用或卸载**一个，体会"清爽=安全"。
4. **（进阶）** 对照官方开发文档，跑通一个**最简单的自定义技能**（哪怕只是返回一句"你好"），重点把 `description` 说明书写清楚。
5. **（进阶）** 挑你工作中一个私有系统 / 常用 API，按 4.6 的四步法**先在纸上设计**接入方案（说明书怎么写、认证怎么放、返回怎么整理成人话），暂不写代码也可以。

> **提示**：练习 2 和 3 哪怕你完全不碰代码，也务必做——它们是本章性价比最高、且立刻能让龙虾更好用的部分。
